Workflows can be written in TypeScript or JavaScript. They are stored in the `.relagit/workflows` directory of your repository.
If you create workflows directly inside of the workflows folder, they **must** be contained in single modules and **cannot** import other modules.

However, we suggest you use a bundler like [vite](https://vitejs.dev) or [esbuild](https://esbuild.github.io) to bundle your workflows into a single module.
This allows you to leverage the full powers of TypeScript and import other modules and packages.

## Building a workflow with Vite

This section will go over how to create a basic workflow using vite and TypeScript. You'll learn about `relagit:` modules and how the hook system works.

### Setting up vite

We'll start by scaffolding a new vite project to work in. We'll use pnpm as our package manager, but you can use npm or yarn if you prefer.

```sh
pnpm init
pnpm add -D vite typescript
mdkir src
touch src/index.ts
touch src/native.ts
touch vite.config.ts
```

We'll then place the following code in `vite.config.ts`. This defines how vite will process our workflow.

```ts
import { defineConfig } from "vite";
import { builtinModules } from "node:module";

export default defineConfig({
    build: {
        target: "esnext",
        outDir: "dist",
        emptyOutDir: true,
        lib: {
            entry: ["src/index.ts", "src/native.ts"],
            formats: ["es"],
            fileName: (_, name) => `${name}.js`,
        },
        rollupOptions: {
            external: builtinModules.concat("relagit:actions"),
        },
    },
});
```

Now, time to get onto the workflow itself.

---

> [!TIP]
>
> RelaGit's JavaScript runner defines a few custom modules that you can `import` or `require` from your workflow.

We'll use these inside of our workflow to interact with the user's repositories and Git.

Let's start by importing `Workflow` and `context` from actions.

```ts
// @noErrors
import { Workflow, context } from "relagit:actions"; // [!code highlight]

export default new Workflow({
});
```

We can now define some basic metadata that will identify our workflow.

```ts
import { Workflow, context } from "relagit:actions";
// ---cut-before---
export default new Workflow({
    name: "My Workflow", // [!code ++]
    description: "A workflow that does something.", // [!code ++]
});
```

We can now start defining our workflow's hooks. Hooks are functions that are called at certain points in a repository's lifecycle.

For example, the `navigate` hook is called when a user switches between a repository or file, while the `commit` hook is called after a user commits their changes.

Each hook has unique parameters that are passed to it. You can find the parameters for each hook in the workflow types.

```ts
import { Workflow, context } from "relagit:actions";
// ---cut-before---
export default new Workflow({
    name: "My Workflow",
    description: "A workflow that does something.",
    hooks: {
        navigate(_, repo, file) {
                        // ^?
            
        },
        commit(_, repo, commit) {
                        // ^?

        },
    },
});
```

Our workflow will be a simple one that counts how many times a user has commit via RelaGit. 
But that brings up a new question: how do we interact with `fs` and other node modules?

To run native (main process) code, we'll have to leverage the other file in our project: `native.ts`.

```ts
// native.ts
import * as fs from "node:fs";
import * as path from "node:path";

const __dirname = path.dirname(new URL(import.meta.url).pathname);

export async function incrementCommitCount() {
    const file = path.join(__dirname, "./storage.json");

    if (!fs.existsSync(file)) {
        fs.writeFileSync(file, JSON.stringify({ count: 0 }));
    }

    const data = JSON.parse(fs.readFileSync(file, "utf-8"));

    data.count++;

    fs.writeFileSync(file, JSON.stringify(data));
}
```

This file will be run in the main process, so we can use node modules like `fs` and `path` without any issues.
Now how do we access this function from our workflow?

We'll use the `native` global value. This value is automatically assigned when RelaGit runs your workflow.

```ts
const native = {
    incrementCommitCount: async () => {},
}
// ---cut-before---
import { Workflow, context } from "relagit:actions";

export default new Workflow({
    name: "My Workflow",
    description: "A workflow that does something.",
    hooks: {
        commit() {
            native?.incrementCommitCount(); // [!code highlight]
                    // ^|
        },
    },
});
```

Let's test our workflow out. We'll start by building it with vite.

```sh
pnpm vite build
```

This will create a `dist` folder with our workflow inside of it. But there's two last steps before we can test it out.

First, we'll need to create a `relagit.json` file in the `dist` folder. This file will tell RelaGit how to run our workflow.

```json
{
    "plugin": "dist/index.js",
    "native": "dist/native.js"
}
```

Then, you'll need to add the filepath to your project's folder to `external.json` as described in the [Installing Workflows](/docs/workflows/installing-workflows#installing-from-the-filesystem) section.

Finally, open up RelaGit and check to see your workflow in Settings > Workflows. If it's there, you're good to go!
